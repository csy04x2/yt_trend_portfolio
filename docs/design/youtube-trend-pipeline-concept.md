# 유튜브 채널 콘텐츠 트렌드 분석 파이프라인 — 구상안 (초안 v0.1)

- 작성일: 2026-09-09
- 상태: 브레인스토밍 정리. 수치·범위는 실제 데이터 확인 후 조정 예정
- 기본 구조: 분석 노트북이 결과를 파일로 만들고, 서비스가 그 파일을 읽어 보여주는 2단 구조

---

## 1. 한 줄 정의

채널 URL 하나를 넣으면, 그 채널의 영상을 콘텐츠 유형으로 나누고, 유형별로 어떤 반응(조회·좋아요·댓글)을 얻었는지와 시청자가 무엇을 칭찬하고 무엇을 지적하는지를 한 장의 리포트로 돌려주는 도구.

핵심 질문은 "어떤 영상이 잘 됐나"가 아니라 **"어떤 종류의 영상이 잘 되고, 왜 잘 됐다고 시청자가 말하는가"**다.

---

## 2. 누가, 무엇을 결정하기 위해 쓰는가

| 사용자 | 결정 |
|---|---|
| 채널 운영자 / 콘텐츠 기획자 | 다음 영상의 주제·형식·길이 |
| 채널 분석을 의뢰받은 마케터·기획자 | 협업 채널 선정, 벤치마킹 |
| 포트폴리오 열람자 | 파이프라인 설계 역량 확인 |

리포트는 "결론 → 근거 → 상세" 순서로 읽히게 만든다. 독자가 숫자를 해석하는 것이 아니라, 결론 문장을 읽고 근거 댓글을 확인하는 흐름이다.

---

## 3. 파이프라인이 답하는 질문 4가지

1. 이 채널의 영상은 어떤 유형으로 나뉘는가 (주제·형식·길이)
2. 유형별로 반응이 어떻게 다른가 (조회 배수·좋아요율·댓글율)
3. 잘 된 유형에서 시청자는 무엇을 칭찬하고, 안 된 유형에서 무엇을 지적하는가
4. 시간이 지나며 잘 되는 유형이 바뀌고 있는가

---

## 4. 데이터 소스와 제약

YouTube Data API v3 (공개 데이터, 로그인 불필요)

| 항목 | 가능 | 비고 |
|---|---|---|
| 영상 제목·설명·태그·길이·업로드일 | O | |
| 조회수·좋아요·댓글 수 | O | 현재 누적치만 제공. 업로드 후 N일 시점 값은 없음 |
| 댓글 본문·작성자·작성일·댓글 좋아요 | O | 댓글 허용 영상만. 답글은 별도 호출 |
| 싫어요 | X | 2021년 말 API에서 제거 |
| 구독 전환·시청 지속·클릭률 | X | 채널 소유자 로그인이 있어야 Analytics API로 가능. 이 컨셉에서는 제외 |
| 댓글 작성자의 계정 생성일·타 채널 활동 | 제한적 | AI 댓글 탐지를 축소하는 이유 |

할당량: 기본 하루 10,000 유닛. 댓글 100개 조회 = 1 유닛 수준이라 영상 50개 × 댓글 200개는 하루 안에 수집 가능. 대형 채널 전체 수집은 며칠에 걸쳐 나눠야 한다.

## 5. 파이프라인 구조

```
채널 URL
 │
 ▼
[1] 수집      영상 메타 + 통계 + 댓글  →  영상 표 (1행 = 영상 1개)
                                        →  댓글 표 (1행 = 댓글 1개)
 │
 ▼
[2] 정규화    조회 배수, 좋아요율, 댓글율 계산 (영상 표에 열 추가)
 │
 ▼
[3] 유형화    제목·설명·태그 임베딩 → 군집 → LLM이 군집 이름 부여 (영상 표에 유형 열 추가)
 │
 ▼
[4] 필터      스팸·홍보 댓글 제거, 의심 댓글 표시 (댓글 표에 열 추가)
 │
 ▼
[5] 감성      긍정 / 부정 / 중립·무관 (댓글 표에 열 추가)
 │
 ▼
[6] 주제      피드백 주제 분류, 고정 8종 + 기타 (댓글 표에 열 추가)
 │
 ▼
[7] 결합      영상 표 ⨝ 댓글 집계  →  유형 × 성과 × 피드백 표
 │
 ▼
[8] 리포트    채널 리포트 화면
```

[1]~[7]은 한 번 실행되어 파일을 남기고, [8]은 그 파일을 읽어 보여준다. 학습·분석과 서비스는 완전히 분리되며, 중간 파일이 둘을 잇는 유일한 접점이다.

### 5.1 수집

- 입력: 채널 URL (handle, /channel/ID, /c/name 세 형식 모두 채널 ID로 변환)
- 영상 표 열: video_id, title, description, tags, duration_sec, published_at, view_count, like_count, comment_count, thumbnail_url
- 댓글 표 열: comment_id, video_id, author, text, published_at, like_count, is_reply
- 저장: CSV 또는 parquet 두 파일. 재수집 없이 이후 단계를 반복할 수 있게 한다

### 5.2 정규화 — 조회수를 그대로 비교하지 않는다

3년 전 영상과 지난주 영상의 누적 조회수는 비교 대상이 아니다.

| 지표     | 계산                             | 의미                            |
| ------ | ------------------------------ | ----------------------------- |
| 조회 배수  | 조회수 ÷ (같은 기간 업로드 영상들의 조회수 중앙값) | 채널 평균 대비 몇 배인가. 시간 보정의 1차 근사  |
| 일평균 조회 | 조회수 ÷ 업로드 경과일                  | 보조 지표. 오래된 영상에 불리하므로 단독 사용 금지 |
| 좋아요율   | 좋아요 ÷ 조회수                      | 시간 영향이 적어 "평가"에 가장 가까움        |
| 댓글율    | 댓글 수 ÷ 조회수                     | 반응의 강도. 긍정·부정 양쪽 모두 올림        |

주의: 조회 배수의 기준 기간(예: 같은 분기)은 실제 데이터를 보고 정한다. 업로드 빈도가 낮은 채널은 기간을 넓혀야 한다.

### 5.3 유형화 — 결과 품질을 결정하는 단계

두 방식이 있고, 첫 버전은 자동을 쓴다.

| 방식 | 장점 | 단점 |
|---|---|---|
| 수동: 채널을 보고 유형 5~8개를 미리 정의 | 정확, 해석 쉬움 | 채널마다 다시 해야 함, 자동화 불가 |
| 자동: 제목+설명+태그를 임베딩 → 군집화 → LLM이 군집 이름 부여 | 채널을 몰라도 동작 | 군집 수 결정, 이름 품질이 LLM에 의존 |

자동 방식 절차:
1. 제목·설명 앞 200자·태그를 합쳐 텍스트 하나로
2. 임베딩 모델로 벡터화
3. 군집화 (k는 영상 수의 제곱근 근처에서 시작, 실루엣 점수로 조정)
4. 군집별 제목 10개를 LLM에 주고 "이 묶음을 한 단어~한 구절로 이름 붙여라"
5. 길이(쇼츠/일반/롱폼)는 별도 축으로 유지. 주제 유형과 교차해 본다

검증: 군집 결과를 사람이 한 번 훑고, 명백히 잘못 묶인 것이 20%를 넘으면 k를 바꾸거나 수동 방식으로 전환한다.

### 5.4 필터 — 스팸·홍보

규칙 + LLM 2단.

- **규칙 (싸고 빠름): URL 포함, 같은 작성자의 동일 문장 반복, 이모지 비율 과다, 극단적으로 짧은 정형 문구 ("first", "👍👍👍")**
- LLM: 규칙을 통과한 댓글에 "홍보·스팸·무관 여부"를 물음

AI 생성 댓글: 텍스트만으로는 신뢰도 있게 탐지할 수 없고(업계·학계 공통 결론), 공개 데이터로는 계정 행동 신호를 모을 수 없다. 이 컨셉에서는 "탐지" 기능을 두지 않고, 규칙 단계에서 잡히는 "동일 문구 반복"만 의심 표시로 남긴다.

### 5.5 감성

- 분류: 긍정 / 부정 / 중립·무관 (잡담, 질문, 영상과 무관한 내용은 무관으로)
- 방식: LLM API. 라벨 데이터가 없으므로 직접 학습은 하지 않는다. 댓글 1만 건 기준 비용 수 달러
- 반어 처리: 프롬프트에 반어 예시를 포함. 확신도가 낮은 것은 별도 표시
- 향후: 교정 데이터가 수천 건 쌓이면 작은 분류 모델로 대체해 비용·속도 개선

### 5.6 주제 — 피드백 분류 체계 (고정 8종 + 기타)

| 코드 | 주제 | 예 |
|---|---|---|
| T1 | 정보·내용 | 유익하다, 틀렸다, 깊이가 부족하다 |
| T2 | 편집·연출 | 편집이 빠르다, 자막이 좋다, 효과음이 과하다 |
| T3 | 길이·구성 | 너무 길다, 본론이 늦다, 딱 좋은 길이 |
| T4 | 출연자·진행 | 목소리가 좋다, 발음이 안 들린다, 텐션 |
| T5 | 썸네일·제목 | 낚시다, 제목과 내용이 다르다 |
| T6 | 음질·화질 | 소리가 작다, 화질 |
| T7 | 요청·제안 | 다음엔 X 해주세요, Y 편 원해요 |
| T8 | 감정·응원 | 힘내세요, 웃겼다, 감동 |
| T9 | 기타 | 위 어디에도 안 들어감 |

댓글 하나에 주제 여러 개 허용 (다중 라벨). T9 비율이 25%를 넘으면 분류 체계를 다시 본다.

### 5.7 결합 — 최종 분석 표

댓글 표를 영상별로 집계한 뒤 영상 표와 붙이고, 다시 유형별로 집계한다.

영상 단위 집계 열: 유효 댓글 수, 긍정 비율, 부정 비율, 주제별 언급 수, 대표 댓글 (긍정 상위 3, 부정 상위 3 — 댓글 좋아요 수 기준)

유형 단위 집계 열: 영상 수, 평균 조회 배수, 평균 좋아요율, 평균 댓글율, 긍정 비율, 긍정 주제 상위 3, 부정 주제 상위 3

시간 축: 분기별로 유형의 조회 배수와 긍정 비율 추이

### 5.8 리포트

정보 구조 (위에서 아래로 읽는 순서):

1. **한 줄 결론** — "이 채널은 X 유형에서 Y 때문에 반응이 좋고, Z 유형은 W 불만이 반복된다"
2. **채널 요약** — 영상 수, 기간, 유형 분포
3. **유형별 성과표** — 유형 · 영상 수 · 조회 배수 · 좋아요율 · 댓글율 · 긍정 비율
4. **유형별 피드백** — 긍정 주제 상위 3 + 대표 댓글 원문, 부정 주제 상위 3 + 대표 댓글 원문
5. **시간 추세** — 분기별 유형 성과
6. **영상 상세** — 개별 영상 표 (탐색용)

대표 댓글 원문이 신뢰의 핵심 장치다. 수치만 있으면 독자는 의심하고, 원문이 붙으면 납득한다.

화면 구현: 첫 버전은 Gradio (빠름). 레이아웃 자유도가 필요해지면 Streamlit 또는 별도 프론트로 교체. 리포트 본체는 HTML/PDF로 내보내기 가능하게 한다.

## 7. 한계와 리스크

- **시간 보정의 근사성.** 누적 조회수만 있어 "업로드 후 30일 성과"를 정확히 알 수 없다. 조회 배수는 근사치이며 리포트에 그렇게 표기한다.
- **댓글은 시청자의 일부.** 댓글을 다는 사람은 전체 시청자의 극소수이고 극단적 의견이 과대 대표된다. 감성 비율을 "시청자 여론"으로 읽지 않도록 리포트에 명시한다.
- **유형화 품질.** 제목이 비슷한 형식으로 반복되는 채널은 잘 묶이지만, 제목이 자유로운 채널은 군집이 흐려진다. 수동 전환 기준(5.3)을 둔다.
- **LLM 분류의 비결정성.** 같은 댓글이 실행마다 다르게 분류될 수 있다. temperature 0, 프롬프트 버전 기록, 결과 캐시로 대응한다.
- **댓글 비활성 영상.** 댓글이 꺼진 영상은 성과 분석만 되고 피드백 분석은 빠진다. 리포트에 표시한다.
- **API 정책 변화.** 할당량·필드는 바뀔 수 있다. 수집 단계를 독립 모듈로 두어 교체 가능하게 한다.

## 8. 단계별 로드맵

| 단계 | 범위 | 산출물 |
|---|---|---|
| 0. 데이터 확인 | 채널 1개, 영상 20개, 댓글 각 100개를 API로 뽑아 실제 필드와 분포 확인 | 영상 표, 댓글 표 샘플. 이 결과로 5.2의 기준 기간과 5.6의 주제 체계를 조정 |
| 1. 최소 파이프라인 | 수집 → 정규화 → 유형화 → 스팸 필터 → 감성 → 주제 → 결합 | 유형 × 성과 × 피드백 표 (CSV) |
| 2. 리포트 | 5.8 정보 구조대로 Gradio 화면 | 배포된 데모 URL |
| 3. 검증·교정 | 분류 결과 200건을 사람이 채점, 정확도 측정, 프롬프트 개선 | 정답 세트, 정확도 수치 |
| 4. 확장 (선택) | 채널 여러 개 비교, 채널 소유자 로그인으로 구독 전환 지표 추가 | — |

0단계를 먼저 짧게 하는 이유: 실제 데이터는 기대와 다르게 나오는 경우가 많다. 화면을 먼저 그리면 없는 데이터를 전제로 설계하게 된다.
