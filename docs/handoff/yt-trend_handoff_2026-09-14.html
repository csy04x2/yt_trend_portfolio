yt-trend 작업 인수인계

기준일: 2026-09-14 · 침착맨 Feature Extractor / Stage 2 evidence 수집
오늘 결론
대규모 수동 라벨링 대신 자동 Feature Extractor + 제한된 Human audit 방향으로 전환했다. guest_present를 1차 벤치마크 feature로 사용하며, Stage 1 metadata가 명확한 경우에는 높은 정밀도로 자동 판정하고, U(불확실)만 Stage 2 caption + frame evidence로 escalation하는 cascade를 채택했다.

1. 현재 제품/분석 방향

제품 문장: 유튜브 채널의 최근 영상들을 자동 분석해, 그 채널에서 어떤 콘텐츠 특성이 평소보다 높은 성과 및 시청자 반응과 반복적으로 연결되는지 찾아주는 도구.

  • Content Feature → Audience Behavior → Performance → Time/Repeatability
  • 절대 조회수보다 Observed vs Expected 상대성과를 중시
  • Feature discovery/정의와 performance 검증을 분리
  • U는 0으로 취급하지 않음
  • Holdout은 계속 sealed
  • 대규모 human full-labeling은 중단. Human은 자동 extractor audit/reference 역할

3. guest_present 정의

guest_present: 침착맨 외 인물이 콘텐츠 참여자로 등장.
제외: 스태프, 배달원, 단순 배경 인물, 외부 영상 속 인물만 등장하는 경우.

4. Human reference / benchmark

기존 56-cell pilot + partial guest family review를 Human reference로 활용한다. 이 Human 작업은 전체 90개를 끝까지 수동 라벨링하기 위한 것이 아니라, extractor 검증용 gold/reference다.

중요 수정: X_sZRLpRPTM (“침착맨이 감사를 전하는 방법”)은 처음 Human 0으로 기록되었지만, 실제로 뒤쪽에 guest가 등장해 Human label = 1로 수정됨. 이 사례는 metadata false positive가 아니라 Human viewing error였다.

6. Stage 2 — Evidence escalation 설계

Stage 1에서 U인 영상만 자동 evidence 수집:

  1. caption/subtitle 수집
  2. 저화질 임시 영상 다운로드
  3. Shorts: 10/30/50/70/90% 지점 frame 추출
  4. metadata + caption + frames + frozen definition으로 multimodal judge
  5. 0/1/U + confidence + grounded evidence 출력

성능/댓글/반응 데이터는 extractor 입력에서 금지.

발견한 문제와 해결

문제 1 — yt-dlp PATH
yt-dlp.exe가 Python user Scripts 폴더에 설치되어 PATH에서 발견되지 않음.
해결: v0.2부터 py -m yt_dlp 방식 사용.
문제 2 — Chrome cookie DB lock
ERROR: Could not copy Chrome cookie database
Chrome 쿠키 사용 시 15개 모두 evidence_failed.
해결 확인: --cookies-from-browser chrome을 제거하고 1개를 재실행한 결과:
evidence_ready = 1, frames = 5, caption = True.
즉 runner 자체는 정상이고 cookie 옵션이 실패 원인이었음.

9. 아직 안 한 일

  • Stage 2 전체 15개 evidence 수집 완료
  • 15개 multimodal guest_present 자동 판정
  • Human gold와 blind comparison
  • 최종 cascade coverage / accuracy / precision / recall 계산
  • 실패/남은 U의 error source 분류
  • 그 뒤에만 all-feature 확장 여부 판단

10. 확장 금지 / 보류

현재 단계에서 아래는 구현하지 않는다:
  • speaker diarization
  • face recognition / host-face clustering
  • full-video embedding
  • 12개 feature 전체 자동화
  • 대규모 manual labeling
15-case Stage 2 평가가 먼저다.

11. 14F 상태

  • 14F 300 videos / 90-90-120 split 완료
  • 친구 Human analyst B가 blind Feature Discovery 진행 중
  • 친구 결과 freeze 전에는 14F LLM 결과를 사용자에게 노출하지 않음
  • 14F는 대규모 2차 실험이 아니라 minimal cross-channel sanity check

12. 팀원이 바로 이어서 할 일

  1. 침착맨 Stage 2 15개를 쿠키 없이 실행
  2. stage2_output 전체를 zip
  3. 15개 frame/caption evidence로 guest_present 자동 판정
  4. 판정 freeze 후 Human reference와 비교
  5. 최종 cascade metric을 보고 all-feature 자동화로 확장할지 결정

주의: Stage 2 수집/판정은 Development benchmark 검증용. Holdout 120은 계속 sealed 상태를 유지한다.
