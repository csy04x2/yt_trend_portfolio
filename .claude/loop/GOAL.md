# 루프 목표

`rule-tuner` 서브에이전트가 반복해서 개선하는 대상과, 언제 멈추는지.

## 대상

댓글 규칙 필터 (`backend/app/pipeline/rules.py`) 하나다.

지금 튜닝할 Claude 프롬프트가 없기 때문이다 — 파이프라인 6단계 중 코드가 있는
것은 03 수집과 06 댓글 선별의 규칙 절반뿐이고, Anthropic API를 부르는 줄은
한 줄도 없다. 05·07·08은 아직 구현 전이다.

## 목표치

`backend/app/eval.py`의 `GOAL`이 정본이다. 세 조건을 모두 만족하면 멈춘다.

| 지표 | 목표 | 왜 |
|---|---|---|
| `false_drop` (오탐) | **0** | 규칙이 확정 제외한 댓글은 리포트에 영영 안 나온다. 조용히, 복구 불가능하게 사라진다 |
| `accuracy` | **100%** | 라벨한 표본을 전부 맞춘다 |
| `samples` | **25건 이상** | 표본이 적으면 100%가 의미 없다 |

`missed`(홍보·선점을 통과시킴)는 목표에 넣지 않았다. 통과한 것은 다음 단계
LLM이 다시 보므로 오탐보다 훨씬 덜 위험하고, 미탐을 줄이려다 오탐을 늘리는 것이
가장 나쁜 거래다.

## 지금 상태와 함정

현재 점수는 **오탐 0 · 정확도 100% · 표본 25건**이다. 목표를 이미 만족한다.

그런데 이건 **표본 25건을 우리가 손으로 썼고 규칙을 거기 맞춰 짰기 때문**이다.
같은 25건으로 루프를 돌리면 배울 것이 없고, 오히려 그 25건에 과적합된다.

그래서 지금 루프가 할 실제 일은 규칙을 만지는 것이 아니라 **표본을 늘리는 것**이다.

1. YouTube API 키를 받아 실제 채널을 `collect` 한다 (비용 0)
2. 실제 댓글 20~30건에 사람이 `_expect`를 달아 `backend/fixtures/labeled/`에 넣는다
3. 그러면 대개 오탐이 나타난다 — 그때부터 루프가 규칙을 좁힌다

DB가 비어 있는 동안에는 루프를 돌려도 할 일이 없다. `rule-tuner`는 그 사실을
`NOTES.md`에 적고 멈추도록 되어 있다.

## 기록

- `HISTORY.md` — 세션마다 훅이 자동으로 남긴다. 점수, 변경 파일, 에이전트 메모
- `NOTES.md` — 에이전트가 이터레이션마다 덮어쓴다. 훅이 HISTORY로 옮기고 비운다

훅은 숫자와 시각만 안다. "무엇이 잘 안 됐는지"는 에이전트가 NOTES.md에 쓴다.

## 돌리는 법

```
/loop 30m Task rule-tuner: 한 이터레이션 진행
```

또는 간격 없이 자기 페이스로:

```
/loop Task rule-tuner: 한 이터레이션 진행
```

목표를 만족하면 `app/eval.py`가 종료 코드 0을 내므로, 에이전트가 그것을 보고
"더 할 일 없음"을 NOTES.md에 적고 루프를 멈추면 된다.
